Баз�� знаний
-----------
knowledge_base/articles.json - десять статей по пяти категориям:
две про оплату, две про технику, две про доступ, две про доставку и одна
для прочих обращений. Агент загружает файл при старте.

Правила поиска, зафиксированные в задании 1
--------------------------------------------
1. Оценка релевантности - доля значимых слов запроса, встречающихся
   в статье.
2. Статья подходит при оценке не ниже 0.25 (MIN_CONFIDENCE).
3. При нескольких подходящих выбирается лучшая; при равенстве - меньший
   номер статьи, чтобы выбор был воспроизводимым.
4. Если ничего не найдено - found: false, это сигнал для эскалации, а не
   ошибка.

Дополнительное правило: совпадение категории обращения со статьёй
добавляет 0.2 к оценке. Без этого запрос про оплату мог получить статью
про доставку, если в ней встретилось бы слово «заказ».

Сопоставление слов по основе
----------------------------
Слова сравниваются не точно, а по основе: запрос «оплатить» находит статью
со словом «оплата». Сравнение по точному совпадению дало бы нулевую
выдачу на реальных обращениях, где почти всегда есть окончание.

Ошибка, найденная при первой проверке
------------------------------------
Первая версия агента поиска не нашла ни одной статьи: уверенность
всегда была 0.2, то есть ноль совпадений по словам. Две причины:

1. Функция isWordRune возвращала true для пробела и дефиса, а условие
   beforeOK требовало !isWordRune. Получалось, что совпадение на границе
   слова никогда не засчитывалось: перед словом в тексте всегда стоит
   пробел.
2. Сравнение было точным, поэтому «оплатить» не совпадало с «оплата».

Исправлено: слова разбиваются на список и сравниваются по основе
(общая часть не короче четырёх символов). После исправления уверенность
стала 0.8-1.0 для типовых обращений.

Ещё одно исправление по ходу проверки: при эскалации оркестратор
показывал клиенту автоматический ответ с пометкой resolved, хотя
обращение ушло человеку. Теперь при эскалации ответ клиенту
подменяется уведомлением о передаче в отдел.
