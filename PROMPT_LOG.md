1. Классификация тикетов — `agents/classifier`
2. Поиск по базе знаний — `agents/knowledge`

4. Эскалация — `agents/escalation`

Для каждого определены роль, входные данные, выходные данные и

  в методичке относится к повышенной сложности и в варианте 2 его нет;

## Задание 3. Разработка оркестратора на Python

### Промпт

> начинай задание 3

### Результат

Оркестратор на `asyncio` и `nats-py` умеет отправлять задание агенту, ждать
результат и обрабатывать таймаут — ровно то, что требует задание.

Раздача ответов сделана через одну подписку на общую тему `ticket.result` и
словарь ожидающих заданий, а не через отдельную подписку на каждое задание.
Причина: агенты публикуют результаты в общую тему, и оркестратор обязан
разнести их по идентификаторам.

Контракт сообщений на стороне Python (`orchestrator/messages.py`) повторяет
Go-контракт: те же имена полей в JSON и те же значения констант. Файлы
закомментированы ссылкой друг на друга, чтобы при изменении правились оба.

### Решения, принятые при проектировации

- Ответ, для которого нет ожидающего задания, не поднимает исключение, а
  пишет предупреждение в лог: иначе зависшее задание или повторный ответ
  приводили бы к падению обработчика подписки.
- При таймауте будущее удаляется из словаря ожидающих. Иначе поздний
  ответ агента остался бы в памяти и ушёл бы в пустоту.
- Счётчик `pending_count` и метод `wait_for_idle` добавлены сразу: они
  нужны для проверок в задании 9, где тесты оркестратора работают с
  моками NATS.
- Параметры повторов (`MAX_ATTEMPTS`, `RETRY_DELAY`) уже есть в настройках,
  хотя сами повторы появятся только в задании 6.

### Неудачные попытки и исправления

| Что пошло не так | Почему | Как исправлено |
|------------------|--------|----------------|
| Первая версия `client.py` импортировала тип `nats.NATS` как значение | В `nats-py` это класс из внутреннего модуля, аннотация ломала проверку типов | Тип подписки и соединения хранится в `Any`, поведение не меняется |
| `pytest.ini` с `asyncio_mode = auto` создан вместе с оркестратором, хотя тестов ещё нет | Нужен был заранее для задания 9 | Оставлен: без него асинхронные тесты pytest-asyncio не запустятся |

### Проверка

- NATS поднят, агент классификатора запущен
- 5 обращений отправлены и классифицированы, время ответа 1.9–5.6 мс
- Таймаут проверен заданием в тему без агента: `TaskTimeoutError` за
  1.01 сек при лимите 1.0 сек
- `wait_for_idle` вернул `True` - зависших заданий не осталось
- Штатное отключение через `drain` и `close` без ошибок
- Мониторинг NATS: 10 входящих и 10 исходящих сообщений
- `ruff check orchestrator` и `ruff format --check orchestrator` - чисто
